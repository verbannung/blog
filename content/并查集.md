# 需求
现场有很多个家族参加活动，现在随便找两个人，需要知道这两个人是否在一个家族内。（假设家族之间不存在联姻，即一个人只属于一个家族)

# 理解
我们可以把每一个家族看成不同的集合，那么这个家族就存在一个代表，我们可以询问这个人你的家族族长是谁，这样我们就可以知道他属于哪一个家族了。
问题抽象成不同集合之中，只需要判断该元素所在的集合的代表元素值相等，即可判断两个不同的元素是否属于一个集合。
这样每一个集合可以看成是一颗单独的树，大家长是根节点。

# 实现

我们可以初始化集合，让每一个元素都是一个单独的集合，想象一下宴会还没有开始，大家零零散散入场。

## 合并
由于现在大家都入场了，我们发现家族A的人有的时候是多来了一个人，有的时候多来了很多人，这个时候我们需要做的就是把这个家族的人纳入到这个集合之中。比如下面的8号需要入场
![[Pasted image 20260827230601.png]]
但是这个时候有一个问题，是把8设定为族长还是把7设置为族长。为了达成扁平化家族管理的目标（树不要太高），所以肯定是把树矮的合并到树高的那一个分支，也就是下面的右侧的方式，这样原来的树并没有增高。
这里我们需要一个额外的rank 秩数组记录每一个集合（也包括子集的树高)，其中只有两侧树一样高的时候，我们的rank 树高才不得不加一

![[Pasted image 20260827230638.png]]
参考代码
``` cpp
void merge(int parent[],int rank[],int x,int y) {
    int px=find(parent,x);
    int py=find(parent,y);
    if (rank[px]<rank[py]) {
        std::swap(px, py);
    }
    //px 的 rank大于py的rank
    parent[py]=px;
    if (rank[px]==rank[py]) {
        rank[px]++;
    }
}
```

    return find(parent,x)==find(parent,y);
}

当然我们这里也提供了另一个版本，用于对象的查询方式，使用字典，hash查找的方式。当然相对于数组的直接寻址，肯定有额外的性能开销
``` cpp

ElementType find(unordered_map<ElementType, ElementType> &parent, ElementType x) {
    if (parent[x] != x) {
        parent[x] = find(parent, parent[x]);
    }
    return parent[x];
}

bool isConnected(unordered_map<ElementType, ElementType> &parent, ElementType x, ElementType y) {
    return find(parent, x) == find(parent, y);
}

void merge(unordered_map<ElementType, ElementType> &parent, unordered_map<ElementType, ElementType> &rank,
           ElementType x, ElementType y) {
    int px = find(parent, x);
    int py = find(parent, y);
    if (rank[px] < rank[py]) {
        std::swap(px, py);
    }
    // px 的 rank 大于 py 的 rank
    parent[py] = px;
    if (rank.at(px) == rank.at(py)) {
        ++rank.at(px);
    }
}
```
